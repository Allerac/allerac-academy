# 4.6 Backlog and priorities

## Problem

Your list of ideas for the page has ten items: dark mode, fix a broken link, new photo, contact section, change the font... You have one hour a week. Where do you start? And what if it were a team of five people with a hundred items?

*Try to think of an answer before you go on.*

## Blocks

### 1. Backlog: everything not done yet
The backlog is the list of tasks waiting their turn. On GitHub, each item is an issue. The backlog is not a promise that everything will get done: it is the team's memory, so no idea or problem gets lost.

> **Tutor notes:** take the guilt out of a big backlog: every project has more ideas than time. Closing an issue with "we won't do this, because..." is also a valid decision.

### 2. Priority: value and effort
For each item, ask two things:
- **Value:** how much does this help the people who use it?
- **Effort:** how much work is it?

Start with what has high value and low effort. A broken link (everyone runs into it, and the fix is quick) comes before a dark mode (nice, but more work).

> **Tutor notes:** this is the value/effort matrix (2x2). Important exception: a problem that stops people from using the product jumps the queue. No numbers needed, "high" and "low" are enough.

### 3. Labels help you see
Labels are colored tags on issues, like `bug`, `enhancement` or `documentation`. With them you can filter the list and see, for example, only the bugs. Many open projects use the `good first issue` label to point out tasks that are good for newcomers.

> **Tutor notes:** every new repository comes with some default labels. Show that you can filter by label in the issue list. `good first issue` is a great way to find a first contribution to an open project.

### 4. A board with columns
GitHub Projects shows issues as cards on a board with columns: **Todo**, **In Progress** and **Done**. You drag the card as the task moves forward. That way everyone sees, at a glance, what is being worked on and by whom.

> **Tutor notes:** this is a kanban board. Golden tip: few things in progress at the same time, ideally one per person. Finishing is worth more than starting.

### 5. How a team agrees
On a team, someone (often a product person) orders the backlog, and the team pulls tasks from the top. Before starting a task, you assign yourself on the issue (**Assignees**) so everyone knows it's yours. Short, frequent conversations, sometimes daily, keep everyone aligned.

> **Tutor notes:** avoid methodology jargon (Scrum, sprints) unless the student asks. Names vary from team to team; what matters is: an ordered list, one task at a time, and saying what you are working on.

## Mission

**On the GitHub website (on any device):**

1. List 4 to 6 improvement ideas for your `my-academy-journal`. AI can help with ideas, but pick the ones that make sense to you.
2. Create a short issue for each one, with a result title and a one- or two-line "Done when". Put a label on each.
3. In the repository's **Projects** tab (or your profile's), create a new project with the **Board** template and add the issues.
4. Order the **Todo** column by thinking about value and effort, and move the first task to **In Progress**. Assign that issue to yourself.
5. Send the tutor the project link (or a screenshot, if the project is private) and explain why you chose the first task.

**Extra (optional):** open the [allerac-academy issues](https://github.com/Allerac/allerac-academy/issues) and see whether any has the `good first issue` label. If you want to take one, comment on the issue before starting and contribute as in lesson 3.6: when you edit a file in a project you don't have access to, GitHub creates a fork (a copy in your account) and the PR comes from there.

**On a tablet or phone:** issues, labels and the board work in the browser. On a tablet the board is comfortable. On a phone, the project's **Table** view is usually easier to use than the board.

**How the tutor checks:** there are 4 to 6 issues with labels, a project with those issues, the **Todo** column ordered, one task in **In Progress** assigned to the student, and a justification of the choice using value and effort.
