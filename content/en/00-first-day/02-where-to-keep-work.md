# 0.2 Where do I keep my work?

## Problem

You changed a document 5 times. Now your boss wants Tuesday's version, but you saved over it. What now?

*Think: how would you avoid this next time?*

## Blocks

### 1. The version problem
"document_final.docx", "document_final_v2.docx", "document_final_REALLY_FINAL.docx"... Everyone has been there. It gets hard to know which version is the right one, what changed and when.

> **Tutor notes:** ask whether the student has been through this. Almost everyone has, and it connects them to the topic.

### 2. Version control
Version control is a system that keeps **every change** you make, with the date, the author and an explanation. You can go back to any earlier version whenever you want.

> **Tutor notes:** analogy: it is like the version history in Google Docs, but much more organized and made for teams.

### 3. What GitHub is
GitHub is a website where teams keep code (and other files) under version control. It is like a Google Drive for code, but with a full history and tools for working as a team.

> **Tutor notes:** the difference between Git (the tool) and GitHub (the website) comes later. Here it is enough to know that GitHub keeps work with its history.

### 4. Why every team uses it
On GitHub, many people work on the same project without messing up each other's work. And everything is public (or visible to the team): who did what and when. Your GitHub profile becomes your real résumé.

> **Tutor notes:** highlight the career side: recruiters look at GitHub.

## Mission

1. Create your account on [GitHub](https://github.com/signup).
2. Add a photo and write a short bio in English (one sentence is enough).
3. Send the tutor the link to your profile.

**How the tutor checks:** the profile exists and has a photo and a bio.
