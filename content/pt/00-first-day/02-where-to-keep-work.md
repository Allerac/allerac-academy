# 0.2 Onde eu guardo o meu trabalho?

## Problema

Você mudou um documento 5 vezes. Agora seu chefe quer a versão de terça-feira, mas você salvou por cima. E agora?

*Pense: como você evitaria isso da próxima vez?*

## Blocos

### 1. O problema das versões
"documento_final.docx", "documento_final_v2.docx", "documento_final_AGORA_SIM.docx"... Todo mundo já passou por isso. Fica difícil saber qual é a versão certa, o que mudou e quando.

> **Notas para o tutor:** pergunte se o aluno já passou por isso. Quase todo mundo já passou, e isso cria conexão com o tema.

### 2. Controle de versão
Controle de versão é um sistema que guarda **cada mudança** que você faz, com data, autor e uma explicação. Você pode voltar a qualquer versão anterior quando quiser.

> **Notas para o tutor:** analogia: é como o histórico de versões do Google Docs, mas muito mais organizado e feito para times.

### 3. O que é o GitHub
O GitHub é um site onde times guardam código (e outros arquivos) com controle de versão. É como um Google Drive para código, mas com histórico completo e ferramentas para trabalhar em equipe.

> **Notas para o tutor:** a diferença entre Git (a ferramenta) e GitHub (o site) fica para depois. Aqui basta saber que o GitHub guarda o trabalho com histórico.

### 4. Por que todo time usa
No GitHub, várias pessoas trabalham no mesmo projeto sem bagunçar o trabalho uma da outra. E tudo fica público (ou visível para o time): quem fez o quê e quando. Seu perfil no GitHub vira seu currículo de verdade.

> **Notas para o tutor:** destaque o lado de carreira: recrutadores olham o GitHub.

## Missão

1. Crie sua conta no [GitHub](https://github.com/signup).
2. Coloque uma foto e escreva uma bio curta em inglês (uma frase basta).
3. Mande para o tutor o link do seu perfil.

**Como o tutor confere:** o perfil existe, tem foto e bio.
