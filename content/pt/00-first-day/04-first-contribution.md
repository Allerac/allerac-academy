# 0.4 Minha primeira contribuição

## Problema

Você encontrou algo confuso neste curso. Como você avisa o time de um jeito que ninguém esqueça e que fique tudo organizado, sem se perder no meio das mensagens de WhatsApp?

## Blocos

### 1. O que é uma issue
Uma issue é um registro de um problema, uma dúvida ou uma ideia dentro de um repositório. Ela fica numa lista, pode ser comentada e é fechada quando resolvida.

> **Notas para o tutor:** analogia: um post-it que não cai da parede e que todo o time vê.

### 2. Como escrever uma boa issue
Uma boa issue responde três perguntas:
- **O que aconteceu?**
- **O que você esperava?**
- **Onde foi?** (qual lição, qual bloco)

> **Notas para o tutor:** mostre um exemplo ruim ("não funciona") e um bom. Peça para o aluno melhorar o exemplo ruim.

### 3. Isso já é trabalho de verdade
Abrir issues claras é uma habilidade real e valorizada. Times de software vivem de bons relatos. Ao abrir sua issue, você já está contribuindo com um projeto da Allerac.

> **Notas para o tutor:** celebre. Este é o primeiro registro público do aluno num projeto real.

## Missão

1. Abra uma issue no repositório [allerac-academy](https://github.com/Allerac/allerac-academy/issues).
2. Conte o que achou do módulo 0: o que ficou claro, o que ficou confuso e o que você mudaria.
3. Use o formato: o que aconteceu, o que esperava e onde foi.
4. O título e o texto podem ser em português: issues sobre o conteúdo do curso são conteúdo, não código.

**Como o tutor confere:** a issue existe, tem um título claro e segue o formato.
